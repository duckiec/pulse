## How To Use This File

1. Tasks are **chronological** — do not start Phase N+1 until Phase N exit criteria
   are met and checked.
2. Before marking any task complete, satisfy the AGENTS.md §4.7 Definition of Done.
3. Check boxes with `[x]` only when 100% complete, tests pass, and MEMORY.md holds
   the corresponding ADL entry.
4. Every completed task must carry honest test disposition (PASSED / FAILED /
   BLOCKED / NOT RUN with reason) per AGENTS.md §4.5.
5. Adding, removing, or reordering tasks requires a MEMORY.md entry.
6. `ROADMAP.md` is the architectural blueprint and scope authority; execution tasks
   trace to its micro-goals (X.X.X). A task that implements, alters, or invalidates
   a roadmap contract requires a MEMORY.md ADL entry naming the affected anchor, and
   a ROADMAP.md update if an interface or exit gate moves.

## Phase 2 — Secrets: OS Keychain, Resolution Chain, Redaction

**Goal:** Zero-trust secret management that touches no disk and never reaches the DB.

### 2.1 Keychain Backends (CGO-free)

- [x] P2.1.2 macOS: shell-out to `/usr/bin/security find-generic-password` (no cgo) — `backend_darwin.go`; refuses a `security` binary outside `/usr/bin` (PATH-hijack guard)
- [x] P2.1.3 Windows: advapi32 `CredRead` via `golang.org/x/sys/windows` — `backend_windows.go`; blob decoded as UTF-16LE, odd-length blobs rejected rather than guessed

### 2.2 Resolver Chain & Ephemeral .env

## Phase 3 — TUI: Bubble Tea Elm Loop, Design System, Zero-Blocking I/O

**Goal:** A 60-FPS terminal UI that renders a 50MB+ streaming response without
blocking the UI thread.

### 3.0 Streaming Transports & Telemetry (Move 5 — landed ahead of the UI)
- [x] P3.0.1 Unified `Stream` interface (`Read`/`Write`/`Close`/`SetDeadline`/`Kind`) with `StreamKind` HTTP|SSE|WS|GRPC; read-only transports return `ErrWriteUnsupported` rather than pretending to accept writes
- [x] P3.0.2 `StreamManager` lifecycle: `Idle → Connecting → Streaming ⇄ Connecting (reconnect) → Closed`, with `Attempts()` and `LastEventID()` observable and `Close()` idempotent
- [x] P3.0.3 SSE parser: resumable state machine over a bounded line buffer (1 MiB cap, fails closed with `ErrOversizeLine`); `Feed` returns `iter.Seq[Event]` from a pre-bound closure, comments counted as heartbeats, id/name interned so a steady flood allocates nothing
- [x] P3.0.4 Reconnect + resume: `Last-Event-ID` retained on the **manager** (not the per-connection parser) and replayed on every attempt; full-jitter backoff 500 ms → 30 s; idle expiry maps to the documented retryable `ErrIdle`
- [x] P3.0.5 Frame-aligned dispatch: events are coalesced and pushed to the Sink at most once per 16 ms frame through the 32 KiB pooled-chunk channel, so an event flood cannot lock the UI
- [x] P3.0.6 Per-read deadline renewal on the live connection (captured via `httptrace.GotConn`), renewed on every read and on every heartbeat; a silent server surfaces as `ErrIdle` instead of wedging
- [x] P3.0.7 `TelemetryReport`: typed httptrace phases (DNS/connect/TLS/wrote/first-byte/got-conn) with monotonic stamps, bounded 512-point ring, lock-guarded `Snapshot()` for concurrent readers
- [x] P3.0.8 eBPF architecture behind strict build tags; absent privileges or a default build report `BLOCKED`/`not-built` **with a reason** and the request proceeds on httptrace timings alone — never a silent fallback
- [x] P3.0.9 Reconnect gate (`TestReconnectReplaysLastEventID`): connection dropped mid-stream, client reconnects and the server observes `Last-Event-ID: evt-2`
- [x] P3.0.10 Mutation evidence: `scripts/mutation-proof-stream.sh` breaks resume-token retention, idle retryability, frame coalescing, and telemetry recording — red → restore → green

### 3.2 Local RAG over the Application Codebase (Move 8)
- [x] P3.2.1 `internal/rag`: concurrent bounded walker + per-language chunking. Fixed worker pool (not a goroutine per file — that is unbounded memory by construction), secret deny-list enforced AT THE WALKER so a `.env`/`.pem` is never opened, documented `.gitignore` subset with anchored rules, and `Index(root, opts…) iter.Seq2[Chunk, error]` as a LAZY generator so a consumer that discards keeps the live set at one file's chunks. Chunks cut at functional boundaries: Go via `go/parser` (compiler boundaries, doc comments included, receiver-qualified symbols), Python via indentation (nested defs get their own named chunks), Astro via frontmatter/script/style/template fences; >64-line declarations windowed with 16-line overlap. Gates: `TestGoChunksCutAtDeclarationBoundaries`, `TestPythonChunksCutAtIndentationBlocks`, `TestAstroChunksSplitAtStructuralFences`, `TestOversizeDeclarationIsWindowedWithOverlap`, `TestDenyListRefusesSecretFiles`, `TestGitignoreSemantics`, `TestWalkStatsAreHonest`, `TestRedactionRunsBeforeStorageAndEmbedding`, `TestTwoIndexRunsAgree`.
- [x] P3.2.2 Embedder interface + pure-Go structural implementation, with the DEGRADED path as a first-class value. `HashingEmbedder` is signed feature-hashing over identifier tokens, sub-word splits and trigrams at d=256 — a real vector, and labelled `structural-hash-v1` everywhere so nothing mistakes it for a semantic embedding. `UnavailableEmbedder` returns `ErrModelUnavailable` rather than a zero vector, because a zero vector ranks as "matches nothing" and the user would be told their code has no similar chunks rather than that the feature is not installed. `onnx-go` is **not vendored**: a model artifact cannot be fetched at runtime (invariant I-3) and none is vendored, so the interface is the seam instead. Gates: `TestEmbeddingIsDeterministic`, `TestEmbeddingSeparatesSimilarFromUnrelated`, `TestCamelCaseIsSplit`, `TestUnavailableEmbedderFailsClosed`, `TestEmptyTextYieldsNoVector`.
- [x] P3.2.3 CGO-free vector storage: FTS5 + brute-force cosine, fused by Reciprocal Rank Fusion. Verified at implementation time that `modernc.org/sqlite` v1.60.1 compiles FTS5 with a callable `bm25()` — probed, not assumed. RRF (k=60) merges two RANKINGS, so no calibration between an unbounded bm25 and a cosine in [-1,1]. The FTS5 query is BUILT, never passed through: error text is full of `"`, `*`, `:`, `AND`, `OR`, `NEAR`, so verbatim `MATCH` would fail precisely when an explanation is needed. Writes batch at 256 chunks/transaction so a concurrent reader waits milliseconds, and each chunk's row and FTS row share the transaction. Tables live in `InitRAG`, not `Open`, so a driver without FTS5 cannot stop Pulse starting. Gates: `TestRAGSchemaSurvivesTheSecretAudit`, `TestFTSQueryCannotBeInjected`, `TestFTSQuerySyntaxErrorIsDetectable`, `TestHybridRetrievalFindsTheKnownChunk`, `TestReciprocalRankFusionPrefersAgreement`, `TestVectorLegOrdersByCosine`, `TestLexicalOnlySearchIsHonestAboutBeingDegraded`, `TestStaleFTSRowsAreReplaced`, `TestUpsertIsBoundedPerTransaction`, `TestCosineMatchesTheRAGPackage`, `TestReindexIsIdempotent`, `TestDeleteByFileRemovesBothLegs`.
- [x] P3.2.4 Contextual error binding: `internal/mcp/error_binder.go`. On a 5xx the error text is extracted from JSON envelopes (string or object form), tracebacks, or a plain body, then the index returns the top-3 chunks attached to the JSON-RPC response. Error text and retrieved source are BOTH redacted — the query reaches an embedding and then a store, so a secret in either is a secret on disk and in a model's context window. A retrieval failure is a DEGRADATION recorded in `warnings`, never a failure of the request: the agent asked to run a request and got a 500, and that is the answer. Gates: `TestFiveHundredBindingIsNotSuppressedOnSuccess` (11 status cases), `TestErrorTextExtraction` (9 body shapes), `TestExtractionIsBounded`, `TestBindingRedactsErrorText`, `TestBindingRedactsRetrievedSource`, `TestRetrievalFailureIsDegradedNotFatal`, `TestDegradedRetrievalIsLabelled`, `TestBindingIsBounded`, `TestNilBinderIsSilent`, `TestStoreRetrieverMapsEveryField`, `TestRenderBindingProducesReadableOutput`.
- [x] P3.2.6 Memory-ceiling gate: 1,000-file corpus, live set asserted independent of corpus size. **The gate had to be rewritten three times because it first measured the wrong thing** — whole-process RSS is dominated by the Go runtime; `HeapAlloc` with GC disabled reports allocation (278 MB) rather than retention; and a sampled `HeapAlloc` peak carries the collector's own policy, swinging between 1.15x and 2.44x on identical source over five runs. It now asserts on the walker's own `PeakBuf` high-water mark — the largest single-file buffer, tracked by the code that allocates it — requiring it NOT to grow while the chunk count does. Measured 3,138 bytes for both 125 and 1,000 files (1.00x). Churn is separately bounded at 256x source. Gates: `TestMemoryCeilingRSS`, `TestMemoryCeilingIsIndependentOfCorpusSize`, `TestMemoryCeilingRSSTotalAlloc`, `TestIndexIsLazyAndBoundedInMemory`.
- [x] P3.2.7 File-descriptor leak gate: exactly zero. `/proc/self/fd` sampled before and after 12 rounds of cancelled walks plus 25 differently-timed aborts so a one-descriptor leak would accumulate past noise; delta asserted `== 0`, not "small". Every early return (oversize, read error, cancelled mid-read, parser fallback) unwinds through one `defer f.Close()`. Gates: `TestFileDescriptorLeakOnCancellation`, `TestFileDescriptorsAreClosedOnEveryPath`, `TestOversizeFileIsSkippedNotRead`, `TestCancelledWalkStopsEarly`, `TestAbandoningTheGeneratorStopsTheWalk`.
- [x] P3.2.8 Mutation evidence: `scripts/mutation-proof-rag.sh` (M25–M31), all red → restore → green with `cmp`-verified restore. M25/M26 the 5xx gate widened/narrowed; M27 FTS5 query passed through verbatim; M28 redaction dropped from retrieved source; M29 the secret deny-list dropped; M30 the vector leg ordering; M31 the consumer's right to stop. **Two boundaries took seven attempts each, and the reasons are recorded in the script rather than tidied away** — M30's obvious divisor mutation is a no-op because `quantize` rescales to L2 length exactly 127 and RRF consumes rankings not scores; M31's cancellation checks are enforced at four independent points, and the seventh attempt deadlocked for 600s, which was a real defect and so the FIX went into the code (termination now cancels a derived context, so one mechanism, no forgotten site, no reachable deadlock).

- [x] P3.3a.3 Strict rate limiter — **GCRA, not a textbook token bucket.** The plain design has a concurrency defect: N waiters all observe "empty", all compute a wait, all sleep the same duration and all wake together, admitting a burst of N and exceeding the configured rate for a full interval afterwards — under exactly the load the limiter exists to prevent. This limiter reserves the slot at DECIDE time instead of WAKE time, giving the single inequality `admission(i) >= t0 + i/R - (C-1)/R`, so **no window of length Δ contains more than `C + R·Δ` admissions**. Cancellation cancels a *derived* context and does NOT refund the slot: a refunded slot lets the run ahead of schedule, which is how "the limiter cancelled cleanly" becomes "the limiter is no longer limiting". A zero/negative rate or a concurrency below 1 is a configuration ERROR, never silently clamped to unlimited. ### 3.4 Wasm Sandboxing for Auth Signing Scripts (Move 11)
- [x] P3.4.1 `internal/wasm/runtime.go`: a wazero sandbox with **no ambient authority at all**. - [x] P3.4.2 `internal/wasm/memory.go`: the memory boundary and the ABI. The guest exports `allocate(size) -> ptr`, `sign_request(ptr, size) -> i32` and `memory`; the host allocates `len + 4 KiB` of headroom, writes the pre-flight envelope, calls the signer, and reads back. **The design deviates from ROADMAP §3.4.2's `(sig_ptr, sig_len)` sketch, and the deviation is the safety argument:** a guest-returned pointer is an address the host must trust, and a bounds check that is wrong is a memory-safety bug in the host. Pinning the output to the buffer the host allocated leaves only a LENGTH as the guest-supplied value, and a length is checked against a buffer the host owns — there is no address for a malicious guest to choose. The host passes the ENVELOPE length, not the capacity, so a guest cannot mistake the reserved tail for content. Every host-supplied range is checked against the LIVE memory size, read at the point of use rather than captured at construction, and `checkRange` subtracts rather than adds so `ptr+size` cannot wrap. Two further measurements shaped what was built. First, a panicking `FunctionListener` does NOT abort a guest call: the panic escapes into the host. - [x] P4.1c.1 `internal/engine/assert.go`: the assertion model.
